HEURISTIC GENETIC CODER LOOP
- `heuristic_genetic_coder.py`
  Uses a bounded generate/mutate/test/select loop for Python candidates.
- Current verified flow:
  1. Receive Aider/user outline.
  2. Build `AskSet`, `SourceSnippetSet`, `ConstraintSet`, `CodeSet`, `TestSet`, `DebuggerSet`, and `EvidenceSet`.
  3. Generate a seed candidate.
  4. Compile with `python -m py_compile`.
  5. Run `test_app.py`.
  6. Build `DebuggerSet` from compiler/runtime output.
  7. Feed bounded repair hints from `DebuggerSet` into the next mutation.
  8. Score fitness and execution likelihood.
  9. Update SOAP-style heuristic weights.
  10. Persist successful code tries to SQLite.
- Smoke result:
  `genetic-1777438289-d5b090df` completed with compile pass, runtime pass, best fitness `0.9072`, and one success record in `genetic_code_successes`.
- GitHub/web snippets are represented as `SourceSnippetSet`; they influence candidate generation but are not run or installed automatically.
- Decompile/compile/debugger support is an adapter inside the genetic fitness loop. Vector35/debugger is a Binary Ninja debugger plugin; when the Binary Ninja/toolchain side is confirmed, its traces should enter `DebuggerSet`, propose bounded fixes, then recompile and pass/fail exactly like the Python-first loop.

- PicoClaw fallback is healthy; native PicoClaw CLI still needs hardening.
- Aider is installed, but local model output quality is uneven. `qwen2.5:3b` is the best current small candidate; several coder-tagged small models produced repetition or malformed replies.
- The genetic coder currently has a Python-first compile/runtime path. C, Rust, Java, D8/APK, and decompile/compile adapters are next phases.
- The debugger adapter path is defined but not fully wired to Binary Ninja yet; current live behavior parses Python compiler/runtime output into `DebuggerSet` repair hints.
- Intel Lava package/hardware is not installed or active yet; the local Lava-ready event plane is active so neuromorphic/event orchestration can be learned safely without destabilizing the now-fast chat path.
- Karoo GP confirms the evolutionary/tree direction but is dataset-oriented; its GitHub page does not define our full code-generation architecture for us.
